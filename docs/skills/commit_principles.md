# Commit Principles for 0700-AAM

This document outlines the commit principles and practices followed in this project, based on the project's contribution guidelines.

## Core Rules

### 1. Developer Certificate of Origin (DCO) Sign-off

**Always sign-off commits** with the `-s` flag to certify you have the right to submit the code:

```bash
git commit -s -m "Your commit message"
```

This adds a `Signed-off-by:` line to your commit, confirming:
- You wrote the code, or have the right to share it
- It can be published under the project's license (AGPL-3.0-or-later)

### 2. AI Tools Attribution

If AI tools (like Mistral Vibe) contributed significantly to the changes, include attribution in the commit message:

```
Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

### 3. Credit Original Authors

Follow the project's code of conduct: **"Share credit. Name the people whose work you build on."**

- Add original authors to `Kick/CONTRIBUTORS.md`
- Include original license information
- Reference source repositories

**Example entry in CONTRIBUTORS.md:**
```markdown
## FSM Kick VST3 Plugin

### Krzysztof Foltman <kfoltman@users.sourceforge.net>
- **Source**: [Buzztrax/buzzmachines](https://github.com/Buzztrax/buzzmachines) (FSM/Kick/)
- **License**: LGPL 2.1 (see buzzmachines/FSM/COPYING)
- **Contributions**: Original FSM Kick synthesis algorithm
```

### 4. Commit Message Format

**Structure:**
```
<Imperative verb>: <Brief description>

<Detailed explanation - optional>

<Attribution - optional>
```

**Use imperative mood** (as if giving a command):
- ✅ `Fix FSM Kick VST3 plugin build on macOS`
- ✅ `Add FSM Kick as internal instrument engine`
- ❌ `Fixed FSM Kick VST3 plugin build on macOS` (past tense)
- ❌ `Fixing FSM Kick VST3 plugin build on macOS` (present continuous)

**Separate subject from body** with a blank line:
```
Fix FSM Kick VST3 plugin build on macOS

- Add missing JUCE audio modules required for VST3 plugin
- Update build-mac.sh to include kickvst_fsm_VST3 target
```

**Explain *what* and *why*, not *how*** (the code shows how):
- ✅ `Add missing JUCE audio modules - VST3 plugin was not linking`
- ❌ `Added juce_audio_basics to CMakeLists.txt because it wasn't there`

### 5. Atomic Commits

Each commit should represent **one logical change**. If you're doing multiple things:
- Fix a build issue
- Add a new feature
- Refactor code

These should be **separate commits**, not one large commit.

## Examples

### Good Commit
```
Add FSM Kick as internal instrument engine for emulator

- Add FSMKickEngine class implementing IInstrumentEngine interface
- Register FSM Kick in InstrumentEngineRegistry alongside Basic Synth and Modular
- Include fsm_kick_engine.cpp in audio_program module source list
- Add fsm_kick_engine.h to audio_program module includes

The FSM Kick engine is now available as a selectable engine type when creating
Plugin programs in the emulator UI.

Parameters:
- Start Freq: Starting frequency of the kick (20-500 Hz)
- End Freq: Frequency the kick decays to (20-500 Hz)
- Tone Decay: How fast the pitch decays (0.001-2 seconds)
- Tone Shape: Curve of the pitch decay (0-1, linear to exponential)
- Amp Decay: Envelope decay time (0.001-4 seconds)
- Volume: Output level (0-1)

Based on FSM Kick Buzz machine by Krzysztof Foltman (LGPL 2.1).

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
Signed-off-by: Your Name <your.email>
```

### Bad Commit
```
fixed some stuff
```
